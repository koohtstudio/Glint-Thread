# Decisions log

One line each: decision, then reason.

- Node 24 LTS installed via nvm and pinned in `.nvmrc`; Sanity 6 and Vitest 5 require Node >= 22.12 and the machine default was 20.19.
- TypeScript 6.0.3 instead of 7.0: typescript-eslint (used by eslint-config-next) supports TS < 6.1 only.
- ESLint 9 instead of 10: eslint-plugin-react (in eslint-config-next 16.4) peers on ESLint <= 9.
- Kept Next 16 Cache Components and Partial Prefetching (create-next-app defaults); data functions use `use cache` + `cacheTag`, and webhook revalidation uses `revalidateTag(tag, { expire: 0 })` per the bundled docs.
- Task list lives in `TASKS.md` because this session has no built-in todo tool; it is updated at each milestone.
- Detail lines containing "verify" (for example "Fibre content: see verify") are hidden on the storefront by `publicDetails()`; they are internal notes, and the facts live in `verify[]` for the Studio.
- Collection rules in products.json are prose; `parseCollectionRule()` turns them into structured rules (tags, max price, sort) so the JSON stays the source of truth.
- "Newest" uses catalogue position in local mode (later entries are newer) because the catalogue has no dates; Sanity mode uses `_createdAt`.
- Colour filter families come from variant names via a fixed vocabulary in `lib/data/derive.ts`; single-variant products fall back to their title ("Emerald Slouch Sling") so the filter still finds them.
- Final sale is derived from category (earrings, hair ties, beauty tools) or a `final-sale` tag, overridable by a product `finalSale` flag in Sanity (PRD 11.1 says "anything marked final sale").
- Children's warning shows for products tagged `kids` (PRD 12.8).
- Images narrower than 600 px are flagged `lowRes` and never rendered wider than their natural width.
- Blur placeholders are 10 px JPEG LQIPs generated by the image copy script into `lib/data/generated/image-meta.json` (committed, keyed by content hash) so tests and builds work without running the script first.
- Content page copy lives in `content/*.ts` as a small markdown dialect converted to Portable Text, so local mode and the Sanity seed share one source.
- Pricing engine marks the paying units of a buy-x-get-y group as promoted too, so overlapping promotions can never reuse them (PRD 9.1 rule 5).
- First-order-only codes (WELCOME10) need an email in the bag; checkout passes it to Stripe as customer_email so the checked email is the one used, and the webhook re-checks redemptions.
- Radix primitives are installed as individual @radix-ui/react-* packages (dialog, accordion, slot, navigation-menu, visually-hidden) instead of the radix-ui umbrella, so only used primitives ship (PRD 13 performance).
- Desktop department nav and mega menu show from 1280 px (xl); below that the header uses the menu sheet, because seven nav items plus a centred wordmark do not fit at 1024 px without crowding.
- Mega menu uses Radix NavigationMenu (120 ms hover intent, click and keyboard, Escape and outside click close it, route change resets it).
- Instant search loads a compact static index (`/api/search-index`) once per visit and searches client-side with the same scorer as the server, so results appear without a request per keystroke.
- Section reveals use `motion` with LazyMotion (features loaded async); hero line reveals and the image settle are pure CSS so they never wait for hydration or delay LCP.
- Bag lines keep a snapshot (title, image, price) for instant rendering; the server quote replaces totals as soon as it returns.
- The footer newsletter column links to the home newsletter band on the home page instead of repeating the form.
- `next/image` uses `preload` instead of the deprecated `priority` prop (Next 16).
- Param-driven pages (shop, collections, products, content pages) export `instant = false`: every param is prerendered by generateStaticParams, so a blocking navigation is served from cache and needs no skeleton fallback (Next 16 instant-navigation validation).
- The home hero starts below the header instead of under it: the PRD's default hero image is white earring cards on black, and the transparent header's wordmark would sit over white card stock. The header is still transparent at the top of the home page and turns ink-950/85 with blur after 24 px.
- The Stripe webhook returns 500 (not 200) when processing a handled event fails, so Stripe retries; handlers are idempotent on event ID, so retries are safe. Unexpected event types still get 200, bad signatures 400.
- Resend replaced Audiences with global Contacts, Segments, Topics and Properties (checked against the installed resend 6 types). RESEND_AUDIENCE_ID is removed; `npm run setup:resend` idempotently creates the "Newsletter" topic (default opt_out, so people are subscribed only after confirming), the "Newsletter subscribers" segment and the consent properties, and prints RESEND_NEWSLETTER_TOPIC_ID and RESEND_NEWSLETTER_SEGMENT_ID.
- The Sanity seed uses createIfNotExists by default so re-running never overwrites prices, stock or copy edited in the Studio; `--force` switches to createOrReplace.
- Orders use private `orders.<uuid>` document IDs as defence in depth; they hold no personal data anyway (PRD 9.8).
- `@sanity/icons` v5 changed its export shape (one module per icon); Studio icons were dropped rather than pinning an old major, Sanity's defaults are used.
- A root `sanity.config.ts` re-exports `sanity/sanity.config.ts` so the Sanity CLI finds it for schema extract and TypeGen (`npm run typegen` writes `sanity.types.ts`).
- In Sanity mode, null stock uses DEV_DEFAULT_STOCK outside production and is treated as untracked in production; the launch check blocks launch while any stock is null.
- OG images are generated with next/og in Instrument Serif; the OFL-licensed TTFs are vendored in assets/fonts because the OG renderer cannot read the woff2 files next/font serves.
- robots.txt also disallows /dev, /newsletter and /search (internal, transactional or thin pages) in addition to the PRD list.
- Adding to the bag opens the drawer (with the new line highlighted) instead of also showing a toast; toasts are kept for stock adjustments, cancelled checkout and errors.
- proxy.ts returns a real 404 for unknown product, collection, shop and page slugs using a cached /api/route-index, because Cache Components streams a 200 for params outside generateStaticParams.
- Privacy (PRD 9.8): orders in Sanity hold only order number, line snapshot, amounts, status, shippingProvince, tracking, Stripe IDs and `emailHash`; the `subscriber` type is gone. Sanity's free plan only has public datasets.
- `emailHash` is SHA-256 of `EMAIL_HASH_SALT:` + the trimmed, lowercased email (lib/email-hash.ts). Order-status lookup and the WELCOME10 first-order check match on it. Outside production a fixed dev salt is used so local mode works with zero env vars; the launch check requires the real salt.
- The pending order stores `emailHash` when the bag supplied an email (first-order codes); the webhook sets it from the Stripe session email. The plain email is never written.
- Confirmation and shipping emails read the customer's email, name and address from the Stripe Checkout Session at send time; shipping email retrieves the session by its stored ID. The owner alert email still includes the customer's name and email (it goes to the owner's inbox, not Sanity).
- /api/admin/* (ship-order, order-customer) authenticate only the Studio user's Sanity token: verified against `https://<projectId>.api.sanity.io/v<api>/users/me`, requiring at least one project role (membership); viewer-only users are refused. ADMIN_ACTION_SECRET is removed. Studio uses token login so the token is available to send.
- Studio Customer panel is a read-only, never-written `customerPanel` field on the order with a custom input that loads details live from Stripe via /api/admin/order-customer; the "Open in Stripe" link picks the test or live dashboard from the `cs_test_`/`cs_live_` session prefix, so it works before loading.
- Newsletter double opt-in signs the consent timestamp, source and consent text version (`newsletter-consent-v1` = the checkbox wording in messages/en-CA.json) into the confirm link. On confirmation one `contacts.create` call writes the Resend contact properties (`consent_text_version`, `consent_at`, `signup_source`, `confirmed_at`), opts the contact into the Newsletter topic and adds it to the segment; an existing contact falls back to update + topic update + segment add. Unsubscribe sets the topic subscription to opt_out (a global unsubscribe if no topic ID is set). With no IDs set the contact is still saved and a warning is logged; with no Resend key it is logged to the console. Nothing is stored before confirmation.
- Newsletter link tokens are HMACs keyed from EMAIL_HASH_SALT with a separate purpose label, so no extra secret env var is needed.
- The privacy policy page now says contact and shipping details live in Stripe and the newsletter list in Resend, matching the data flows.
- `npm run typegen` deletes the stale `sanity/extract.json` first because the Sanity CLI refuses to overwrite it.

## Scope change: Firebase accounts, own checkout, Stripe for payment only
- Supabase: nothing had been started (no packages, files or env vars), so there was nothing to remove. Firebase Auth + Firestore are used instead, as the owner specified.
- PRD.md updated first (1, 2, 5.3, 6.4, 7.6, 8.1, 8.3, 8.4, 9.1 to 9.9, 10, 10.1, 12, 13, 14, 15, 16); the hosted Stripe Checkout Session, the one-off coupon and Stripe Tax code paths are removed.
- `TAX_MODE` is now `none | table` (the `stripe` mode is gone). The table lives in Sanity `siteSettings`, is seeded from `products.json` `tax.provinces` (2026 rates), and every component has its own applies-to-shipping flag (default on: delivery charges on taxable goods are taxable). Tax is computed in integer maths (rate x 1000 as an integer) and rounded per component; GST labels have no province, HST/PST/RST/QST carry it ("HST (ON) 13%").
- The engine does not model product-specific provincial exemptions; the owner confirms them with an accountant (PRD 7.6). Pickup (disabled by default) is taxed by the address province like any other order.
- Checkout follows the owner's server flow: one `POST /api/checkout/session` creates the pending Sanity order, the Firestore `customerOrders` doc and the PaymentIntent when `/checkout` loads, then updates the PaymentIntent amount on every re-quote. Consequence: abandoned visits leave `pending` orders; they stay out of "To ship" and are harmless, and a cleanup job is on the v2 list.
- PaymentIntent updates are authorised by an HMAC token (bound to order ID and PaymentIntent ID, keyed from EMAIL_HASH_SALT) returned with the first call, so nobody can edit another customer's intent by guessing IDs.
- The PaymentIntent also carries `shipping` and `receipt_email` (payment and fraud checks, and the fallback source for customer details when Firebase is not configured or in Studio). Stripe is still used only for payment.
- `customerOrders` also stores the line snapshot, carrier and tracking so the account order pages need no Sanity read; the Studio "Mark as shipped" action mirrors status and tracking into it.
- The Firebase client SDK loads only on auth pages. Everything else uses the session cookie and our own API routes; a non-sensitive `gt_signed_in` hint cookie tells the bag to sync with Firestore without loading the SDK, so page weight and the static shell are unaffected.
- Session cookie: name `gt_session`, 5-day expiry, `httpOnly`, `secure` in production, `sameSite=lax`. Password change and account deletion require a sign-in within the last 10 minutes (`auth_time`).
- Verification, reset and sign-in links are generated with the Admin SDK and rewritten onto our own `/account/action` page (same `oobCode`), then handled with the client SDK; users never see Firebase's default pages or emails.
- Guests who tick "Create an account" get an email-link sign-in after payment (no password needed, and the link proves the email); they can set a password on the profile page. Guest orders are linked to an account only when the email is verified.
- Sign-up marketing opt-in is stored with its consent record on the profile and only sent to Resend when the email is verified (so it behaves as double opt-in).
- Delete my account: removes auth user, profile, addresses and cart, the Resend contact, anonymises `customerOrders` (keeps order number, lines, totals, tax, dates), and clears `emailHash` on the matching Sanity orders.
- Stripe Appearance loads Manrope through Stripe's own font option so the Payment Element matches the site; the CSP allows Stripe's frames and telemetry hosts and the Firebase Auth hosts, plus emulator hosts only when `NEXT_PUBLIC_FIREBASE_AUTH_EMULATOR_HOST` is set.
- Tests: Firestore rules and account flows run against the Firebase emulators (Java is available). Payment e2e uses the owner's Stripe test keys with the Sanity and Resend variables blanked in the test server's environment so no real order documents or emails are produced; webhook behaviour is tested with signed events built from the test webhook secret.
- Stripe iframes get Manrope from our own `/fonts/manrope-latin.woff2` (copy of the self-hosted subset, CORS header in `next.config.ts`) instead of Google Fonts, so no font CDN sees checkout visitors. Stripe only accepts `https://` font URLs, so on plain-HTTP localhost the iframes fall back to their default face; production is unaffected.
- CSP: emulator hosts (`localhost:9099`) are allowed in development only (`NODE_ENV !== production`), not keyed on the emulator variable; production CSP never lists them.
- Checkout creates the pending order and PaymentIntent when `/checkout` loads with items (PRD 9.2), so the left column shows a skeleton until the first response (about a second) and the forms never remount under the customer's fingers. The session (`orderId`, PaymentIntent, token, client secret) is kept in `sessionStorage` so a refresh reuses the same PaymentIntent; abandoned pending orders simply stay `pending` (hidden from the Studio "To ship" lists and the customer's orders).
- Wallet sheets (Apple Pay, Google Pay) edit the address and shipping method away from the form, so those values are "held" in the session hook until the sheet closes; the PaymentIntent amount is updated on the server and `elements.fetchUpdates()` runs before each `resolve`. Only the province is sent for address changes (wallets share a partial address before authorisation).
- Radio marks in checkout are circles (`rounded-full`) because a square radio would not read as a radio; this is the one exception to "rounded-full only on chips and swatches".
- Underline fields show focus as a 2px champagne bottom border (no outline ring around an underline), matching the PRD focus rule's intent; every other control keeps the global 2px champagne outline.
- Link and Klarna appear in the Payment Element only while the Stripe account has them enabled (test mode shows them regardless). The owner chooses payment methods in the Stripe dashboard; the handover notes say so. ECE is limited to Apple Pay and Google Pay in code.
- The confirmation page is keyed on the PaymentIntent client secret in the return URL (checked against Stripe server-side), so an order number alone never reveals an order; with neither order store configured it shows the total only.
- `getSessionUser()` calls `connection()` before verifying the cookie so the render is request-time under Cache Components (token checks read the clock); account pages sit inside Suspense and redirect to `/account/sign-in?next=...` when signed out.
- Signed-in bag sync merges both bags by SKU (larger quantity wins, capped at 10; local promo code wins), then saves each change after a 1 s debounce; signed-out visitors (no hint cookie) never call the API.
- `proxy.ts` excludes `/account` from the single-segment content-page 404 check.
- Test hygiene: `e2e/test-env.ts` pins a hermetic environment (local catalogue, no Sanity or Resend, Firebase emulators on project `demo-glint`, known webhook secret, TAX_MODE=table) for Playwright and `npm run qa:server`; `NEXT_DIST_DIR` gives QA servers their own build folder so they never clobber `npm run dev`.
- Sanity service setup: the configured `production` dataset was seeded with deterministic, create-if-missing documents and its counts were verified; `.env.local` stays ignored and is set to `DATA_SOURCE=sanity` for the connected environment.
- Stripe local forwarding: CLI 1.53 requires an explicit event list, so the listener forwards only the four PRD payment/refund events; its generated webhook secret is stored only in `.env.local`.
- Test inventory: because all 179 catalogue variants began uncounted, four test variants were temporarily set to 10, decremented by the paid webhook, verified at 7/9/9/9, then restored to uncounted; no owner stock counts were invented.
- Ontario test quote: `.env.local` has `TAX_MODE=none` and no GST/HST number, so the $48.37 test order carries no tax line; tax registration and tax mode remain owner decisions.
- Resend test limitation: the current test-domain API key rejects sends to the configured `OWNER_EMAIL` because it is not the key's permitted test recipient; template sends wait for the recipient to be aligned or a sending domain to be verified.
- Checkout race: a PaymentIntent can succeed between the session's status read and amount update; translate Stripe's `payment_intent_unexpected_state` race to an already-processed response instead of logging a server error after payment.
